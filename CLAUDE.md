# Future Cop: L.A.P.D. — asset extraction & Godot viewer

Reverse-engineering the PS1 game *Future Cop: L.A.P.D.* (EA, 1998): extract every asset
from the disc with Python, and browse all of it in a Godot 4 asset viewer. (The Godot
project also holds a generated, walkable scene for each level.)

## Repo layout

```
parsed/    extractor output, one folder per level (+ parsed/video/) — regenerate with tools/
tools/     Python extractors, lib/ (shared helpers) and run_all.py
godot/     Godot 4.6 project: asset viewer + generated level scenes (assets synced for 4 levels)
README.md  human-facing overview, quick start, how to extract the disc images
```

The game data stays **outside git**, in the repo's parent folder:

```
../Future Cop - L.A.P.D. (USA).iso, ../future_cop_lapd.img/.ccd/.sub   disc images
../ps1/        PS1 disc contents (what the tools read)
  CW/*.MIS       Crime War campaign levels (FE, LAX1, LAX2, M1A1, M2C, M3A, M3B, M4A1, OV, UN)
  PA/*.MIS       Precinct Assault levels (CONFT, HK, OVMP, SLIM, JOKE)
  CW/, PA/       *.LSC loading screens, *.DEM attract-mode demos
  MOVIES/        25 .WVE FMVs;  EA_LOGO.FSV;  SLUS_007.39 = PS1 executable
../pc/windows/ PC disc, ISO 9660 side. MISSIONS/<level> are the PC .MIS files
               (big-endian, forward FourCCs; for comparison only).
../pc/mac/     PC disc, HFS side (Mac version; resource-fork files are MacBinary .bin)
../ghidra/     the analysed Ghidra project of SLUS_007.39 (see External references)
```

Only code is in git. `parsed/` and `godot/assets/` are generated by `tools/run_all.py`
and gitignored, so a fresh clone needs the disc at `../ps1/` and one pipeline run before
the viewer or the level scenes have anything to show. The history was squashed on
2026-10-28; nothing from before then, such as the old `raw/`, `archive/` (BIN/CUE) or the
committed `parsed/`, survives in git.

## Extraction pipeline (`tools/`)

Every script is standalone (`python3 -I tools/<script>.py`) and writes to
`parsed/<LEVEL>/`. They find their inputs with `lib.iff_utils.find_game_files(ext)`, which
returns the sorted `<ps1_dir>/{CW,PA}/*.<ext>` files. `lib.iff_utils.ps1_dir()` is
`$FCOP_PS1_DIR`, or `../ps1` next to the repo. They need Pillow and fonttools;
`extract_videos.py` also needs java and ffmpeg (libtheora).

`tools/run_all.py` runs the steps below in order (`--no-videos`, `--from STEP`), then
`sync_godot_assets.py`. The order matters: objects, terrain and glTF reference the
textures written by `extract_visuals.py`, and `extract_tos.py` checks against `voices/`.

| `extract_objects.py` | `Cobj` 3D models (static, last morph frame) | `objects/cobjNNN.obj/.mtl` |
| `extract_terrain.py` | `Ctil` chunks + `Cptc` grid | `terrain/ctilNNN.obj`, `terrain/map.obj` (stitched, incl. border filler) |

| `export_gltf.py` | `Cobj` incl. skeletons (3DHY/3DMI), morphs (4DVL/3DRF), clips (AnmD), UV anim (3DTA) | `models/cobjNNN.glb` |
| `decode_actors.py` | `Cact`/`Csac` per-class fields (45 classes), `CASt` spawn data | `actors_decoded.json` |

`tools/lib/` holds the shared helpers: `iff_utils.py` (game-file lookup and IFF walker)
and `bs_decode.py` (PS1 MDEC/BS v2 still-image decoder). Tools put `tools/` on `sys.path`
and import `from lib.<module> import …`. Some tools also import other tools'
helpers, e.g. `extract_fun`/`extract_shd` use the VM disassembler in `extract_rpns`.
`sync_godot_assets.py` copies only what `generate_scene.gd` reads from `parsed/<LEVEL>/`
into `godot/assets/<LEVEL>/` and deletes everything else there. Godot's extracted `.glb`
textures (`models/<cobj>_*.png`) are kept.

`lib.iff_utils.iter_iff_resources(data)` is the shared IFF DATA-section walker and yields
`(type, id, payload)`. **It merges resources that share a (type, id)**. Every mission has
two `Csfx` id 1 and two `Cshd` id 1 (a global and a mission table). For those, use the
non-merging `extract_rpns._iter_resources`, which also exposes the SHDR header.

Every script has a detailed format docstring at the top. Read it before changing a parser:
the docstrings are the source of truth for each binary layout. Each docstring states the
confidence of its findings (confirmed vs guessed). Treat the "guessed" actor class layouts
in `decode_actors.py` as hypotheses.

### Format facts that took a lot of trial and error (don't re-derive)

- MIS = EA IFF. The CTRL header holds the MUSIC size at 0x0c, the SWVR size at 0x10 and
  the DATA size at 0x14. The sections follow in the order DATA, SWVR, MUSIC, and the three
  sizes sum to the file size. DATA chunks are aligned to 0x6000, and `LLIF` is fill.
  FourCCs are stored byte-reversed (`bkvC` = `Cvkb`).
- SPU ADPCM: in byte 0, the **low nibble is range/shift** and the high nibble is filter.
  Many docs say the opposite.
- Audio rates confirmed by listening: voice is 11025 Hz mono. Music (MGAV) is 13230 Hz
  stereo, laid out split-half (first half L, second half R), with no end flag.
  - `extract_sfx.py` writes every Cvkb sample at 11025 Hz. According to the Cvkh tone
    tables, 258 tones are really 22050 Hz and 476 are 16000 Hz. That comes from the data
    and hasn't been checked by ear.
  - `sfx_tones/` has each tone at its in-game pitch.
- BGAV clips are grouped by the preceding 36-byte `RVWS` name. Slice the name at the null
  byte, because it is followed by a `\x80` pad. Strip any partial `.stream` suffix as
  well, because the 20-byte field truncates it.
- Cobj vertices: `(-x, y, z) / 512`. Terrain: `world_y = channel_byte / 32`, and each Ctil
  chunk spans ±8 units.
- **Surface bytes:** each Ctil has `polygon_action_types[4]` (after the heightmap and one
  zero byte), and each tile polygon picks one with bits 13–14.
  - Bit 0x80 makes the polygon see-through to the camera. Bit 0x40 marks a floor the game
    walks through, unless its index is 0.
  - The low six bits are an enumeration: water, kill, traction, damage, team zones and
    conveyors. It's decoded in `godot/scripts/surfaces.gd`.
  - Game x/z are the map's z/x.
  - `extract_terrain.py` writes `terrain/surfaces.json` (the special floor triangles) and
    gives the walk-through floors a `cbmpNNN_pass` material. Only JOKE and SLIM have them.
- **Terrain material suffixes** (`extract_terrain.py`), in this order: `_mix`
  (tile-graphics bit 12, semi-transparent: the GPU's 50/50 blend via the textures' alpha
  128), `_s<u>_<v>` (bit 11, UV scroll by the chunk's two signed bytes after the 84-byte
  block: `(s * clock300 >> 6) % 28` texels, 0x80065744), `_see` (surface bit 0x80) and
  `_pass` (always last).
- **Water** is tile type 3: its colour comes from the chunk's `SLFX` light table
  (0x800654f8), not the shading byte (which is 0, so it used to render black). The
  extractor uses the table's mean level (`_slfx_light`); the per-cell flicker of noise
  mode isn't reproduced. Type-0 shading is still `/64` (×2 in Godot), which may be up to
  2× brighter than the game's `shading & 0xfc` with 128 = ×1 (not checked).
- **Y-inversion is only a skinned-model thing.** Skinned Cobj vertices are bone-relative,
  and the root bone carries a 180° rotation about (1,0,1). The OBJ export skips that
  rotation, so skinned OBJs (e.g. the mech) look upside-down. The `.glb` export applies
  the root rotation, so **never flip `.glb` models**. Static and morph models are upright
  either way.
- X1-Alpha (class 1) is five parts, in `objects` order in every level: legs (walk cycle,
  53 clips), cockpit (wing/hover transform), weapon (×2), beacon lights, pilot. They
  mount on the `.glb` `attach_N` empties (3DHS): cockpit on legs.attach_0 and lights on
  cockpit.attach_2. **The weapons are different.** They follow cockpit skeleton bones,
  weapon 0 on `bone_4` and weapon 1 on `bone_2` (end bones under the side bones), via
  `BoneAttachment3D`. The game copies those bones' world matrices (`0x80052960`), with
  no offset or mirroring. Cockpit attach_0/1 sit at the front of the cockpit, where the
  guns were wrongly hung before. `level_layout.assemble_x1()` builds it.
  The legs walk cycle is AnmD tracks 38→39→40→41 (looping); track 0 is rest.
- X1 walker ↔ hover transform (`0x80055988`):
  - Cockpit track 2 (f0–29) and legs track 12 (f330–359) play together over 1.37 s,
    forwards to hover and backwards to walk.
  - Holds: in hover, cockpit track 1 (f29) and legs track 13 (f359); in walker,
    track 0 for both. Cockpit frame 0 = walker, 29 = hover.
  - The body rises 0x1000 (0.5 Godot units). Plain sound 0x15 and player effect 4
    (Csfx table 1, lightning) play at the start of either direction.
  - Hover physics: thrust with 5% drag per 37.5 Hz step, steady 9.4 units/s, capped at
    10.7. They run from the start of either transform until the walker has landed.
  - Hover loops: positional 0x28 (idle) and 0x29 (moving or turning).
- Actor placement: `pos × 8` world units, mapped as in `godot/scripts/level_layout.gd`.
  Cnet nodes use the same `pos_x`/`pos_z` convention (`raw/256`), and every pathed actor
  sits exactly on a node of its net.
- Timing: the game clock advances 5 per VSync (300 Hz on NTSC). Cfun periods, `t[]`
  timers and Csac spawn periods count VSyncs (1/60 s). Model animation (AnmD) runs at
  **10 fps** (3 clock units × 30 per frame; walk tracks scale with actor speed). The CANM
  radio panels are 10 fps and play once.
- RPNS script slots are `on_damage`, `on_destroy` and `on_detect`. A Csac's two SHDR inline
  scripts are its spawn condition and on-spawn action; for other types the second
  inline script is an on-load action.
- Cfun, RPNS and the SHDR script slots all use one RPN bytecode VM. The interpreter is at
  0x80069d68 in SLUS_007.39, with a jump table of 62 opcodes at 0x80011c6c. The opcode
  table is in the `extract_rpns.py` docstring.

### External references

- **fc-mit** (`github.com/Ghoster738/Future-Cop-MIT`, MIT-licensed C++), especially
  `src/Data/Mission/`, is the reference that the terrain, object, glTF, actor, Cnet, Cfun,
  Cshd, Ctos and Cdcs parsers were ported from. Its own bugs that we fixed are noted in the
  docstrings. Clone it into a scratch dir when needed.
- `../ghidra/` (outside git; it was `tools/ghidra_project/` until 2026-10-28) is the
  analysed SLUS_007.39 with PsyQ signatures applied.
  - It needs the `ghidra_psx_ldr` extension (PSX language), which has no Ghidra 12.2 build
    yet. On the Linux box, Ghidra 12.1.4 + ghidra_psx_ldr + a Temurin 25 JDK live in
    `~/.local/opt`.
  - Ghidra refuses project paths containing dot-dirs. The project owner field is `chris`.
  - `../ghidra/decomp.sh <addr>...` decompiles headlessly via `scripts/Decomp.java` (pass
    `list` to list all functions). Each call costs ~1 min of start-up, so batch addresses.
  - Only one process can open the project at a time.
  - The findings (function addresses, layouts) are recorded in the tool docstrings, so
    the project is only needed for further reverse-engineering.
- Video: jPSXdec handles `.WVE`/`.FSV`. It isn't committed: `extract_videos.py` downloads
  the v2.1-beta release on first use, checks it against a pinned SHA-256, and caches it in
  `~/.cache/fc-lapd/` (`JPSXDEC_JAR` overrides). It writes `debug00.log`/`index.log`/`save.log`
  into its cwd, so `extract_videos.py` runs it in a temp dir.

## Godot project (`godot/`)

- Godot 4.6, Forward+. Main scene: `scenes/menu.tscn` (`scripts/menu.gd`), a level-select
  menu that lists the existing `scenes/<LEVEL>_level.tscn`, grouped by disc folder (CW =
  Crime War, PA = Precinct Assault). It previews each level's loading screen, synced to
  `assets/<L>/loading/`, and shows it full-screen while the chosen scene loads in the
  background (`ResourceLoader.load_threaded_request`). Esc in a level returns to it.
  - Linux: `godot` (Godot 4.6.3 in `~/.local/opt`).
  - Mac: `/Applications/Godot.app/Contents/MacOS/Godot`.
- **Asset viewer**: `godot --path godot res://scenes/asset_viewer.tscn`
  (`scripts/asset_viewer.gd`).
  - It reads **`parsed/` directly at runtime**, so all 15 levels work with no copying
    and no import step. `scripts/obj_loader.gd` is a runtime OBJ/MTL loader; glTF,
    PNG, WAV, TTF and Theora files load natively.
  - Categories: Models (glb with animation playback, OBJ fallback), Terrain, Textures,
    Images (particles, loading screens, radio panels, front-end), Fonts, Level, Audio,
    Video and Data (a tree of any JSON).
  - **Level view**: terrain, every actor, and the Cnet paths. Overlays are built by
    `scripts/level_overlays.gd`, each with its own toggle:
    - Decals: class-97 quads from `dcs.json`. Ground decals look right; the orientation of
      tilted ones (x/z rotation) is unverified.
    - Zones: Trigger boxes (yellow), CollisionTrigger cylinders (green) and
      AttachedCollisionBox boxes (magenta). Zones over 8×8 units are outlines only.
      Spawners get purple rings.
    - Ranges: engage/look circles. fov is always a full circle.
    - Heights: the Ctil height channels as R/G/B points.
    - Wiring: script → actor edges from `rpns.json`, `fun.json`, triggering actors and
      attach links.
    - Animate: animated actors use their glTF and loop `all_frames`. 3DTA texture
      animations (lights, screens, water) play through `scripts/uv_animator.gd`.
      - The exporter puts each animation's faces in their own primitive, and each vertex
        follows its nearest frame-0 corner.
      - 13 of the 84 animations skew slightly, so a material UV offset isn't enough.
      - Frame meshes are built once per model and shared; rebuilding per instance made
        LAX1 run at 6 frames/s instead of 145.
      - The Models tab plays them too.
    - Effects: `scripts/effect_player.gd` plays effect definitions approximately.
      - The effect lookup is the Csfx table 0 overlaid with the level's class 87–94
        actors.
      - Effects flagged `placed_at_load` loop at their positions (224 in 8 levels).
      - Selecting an effect actor plays it.
      - Selecting an actor with `BaseEntity.explosion` plays its damage set's
        destruction effect and lists its damage stages.
      - The shared header (repeat, chained next effect, placement) and each class's
        visual are driven by the decoded fields. The size/speed unit scale (fx12, ×8,
        per second) is assumed.
    - Minimap: `scripts/minimap.gd` shows the heightmap and decoded map icons
      (`BaseEntity.map_icon` / `NeutralTurret.map_icon_a`), cropped to the play area,
      with a camera marker. Click to move the camera there.
    - Colour: by team, group or class.
    - Selecting an actor draws its wiring (orange = sends, cyan = receives) and its range,
      and lists spawner details. "Level fn N" entries show a level function's script and
      beam its target actors.
    - The text filter also hides non-matching actors in 3D.
    - Ground tilt (`level_layout.ground_aligned_parts`/`tilt_local`) is applied in both the
      viewer and `generate_scene.gd`.
  - User args after `--` select a view and save a screenshot, e.g.
    `--level M2C --tab Level --item "Cnet 1 " --pitch 60 --shot /abs/out.png`.
    Also `--anim N --seek 0.5` for animations, and
    `--show Heights,Wiring --hide Decals --colour Team` for Level overlays.
- `scripts/level_layout.gd` holds the actor placement shared by the generator and the
  viewer: heightmap sampling, game → Godot position, initial yaw, part stacking and the
  X1 assembly. Change placement there only.
  - Yaw comes from the `STORED_YAW` table: the params word and bits each class's init
    function reads in SLUS_007.39 (see `initial_yaw` in actors_decoded.json).
    - Turret bases have their own yaw (`PART_YAW`).
    - Path followers (5/20/26/28/31) face from their spawn Cnet node towards the next
      node, so the layout needs `nets`.
    - Aircraft and negative prop/pickup values (random or spinning) are left unrotated.
    - This is derived from the code and not yet confirmed visually.
  - Classes 98/99 are weapon definitions and are not placed.
  - Ground tilt follows the decoded "align to terrain normal" flags: DynamicProp
    align_flags bit 0 (no level sets it) and turret base_flags bit 0 (27 turret bases).
- `scripts/generate_scene.gd` is a headless generator. It builds `scenes/<LEVEL>_level.tscn`
  from `godot/assets/<LEVEL>/`, which `tools/sync_godot_assets.py` fills from `parsed/` for
  **all 14 levels with terrain** (every level except FE). These include `nets.json` and
  `models/` (the X1 part `.glb`s); the rest are OBJs.
  ```
  python3 -I tools/sync_godot_assets.py CONFT     # parsed/ → godot/assets/
  godot --headless --path godot --import        # first, or textures fail to load
  godot --headless --path godot --script scripts/generate_scene.gd -- CONFT
  ```
  The committed scenes are pure generator output; there are no hand edits. They reference
  `res://assets/...`, which is gitignored, so they only load after `run_all.py`.
  - **The player** is the first X1-Alpha in `actors.json`. It's a `CharacterBody3D` with
    `player.gd`, a capsule collider and the chase camera. Other X1s stay static.
  - Per-level extras: a Music node from `music/`. Lighting is the same neutral sun in
    every level; the CONFT red sun tint is gone.
  - Animated props (models with clips or 3DTA) and props with MIX/additive/env-mapped materials use
    their `.glb`, keeping the OBJ props' offsets, yaw and ground tilt. The OBJ has no
    blend modes, so CONFT's additive light beams (cobj056–064, `cbmp010_add`) drew as
    solid black slabs. `sync_godot_assets.py` copies a `.glb` only for those props.
  - `ObjLoader.apply_fc_materials()` fixes what glTF can't express. Both the scenes and
    the viewer call it, and the viewer's Level view also uses the `.glb` for these props.
    - `_add` materials become `BLEND_MODE_ADD`; glTF has no additive mode, so they
      import as alpha blending.
    - `_env` (environment-mapped) materials get a sphere-map shader, after fc-mit's
      GLES2 renderer: colour + shine × (1 − texture alpha). The shine is looked up by the
      view-space reflection vector in the 128×128 disc at (0, 124) of the level's
      `cbmp010.png`. Every level has a sphere map there; OV and HK have abstract ones.
      This hasn't been checked against the game's own env-map code.
    - Before this, env-only models such as CONFT cobj063 (the arches on actors 360/362)
      drew near-black.
  - The scene root runs `scripts/level_ambience.gd` (visual/audio; only elevators react):
    - placed effects;
    - class-97 decals (only some levels have them, e.g. M2C 180, UN 88, M4A1 44);
    - looping `all_frames` clips on props (not on the X1 parts);
    - 3DTA texture animations;
    - looping 3D ambient sounds. `BaseEntity.ambient_sound` "sound N" is the Cshd entry
      with **group_id N** (group_id is the sound key), and it plays that entry's tone
      WAV.
    - **Minimap** (bottom right; M toggles): `minimap.gd` from the viewer, tracking the
      walker with a heading tick.
    - **Elevators** (`elevator.gd`, class 10): absolute stop heights from the ground
      probe, the game's speeds and waits, ping-pong; the walker rides an
      AnimatableBody3D (moved directly: moving its parent doesn't sync it). Trigger types
      2/3/4 wait for script messages, so they stay put. Their ambient sound loops only
      while moving. `tile_effect` is the top's surface byte.
    - **Pickups** (class 16) spin at the decoded rate; they don't bob. The power-up
      flash isn't drawn.
    - **Water scroll:** `_s<u>_<v>` terrain materials get a per-frame `uv1_offset`.
    - **Debug overlay** (O; `debug_overlay.gd`): trigger zones labelled with what their
      scripts message, Cnet paths and special floors by colour, built with the
      viewer's `level_overlays.gd` builders. It needs `rpns.json` and `fun.json`.
    - **Lighting:** L toggles the PS1 look (the default: unshaded, no sun, terrain vertex
      colours ×2 because PS1 colour 128 = full brightness) and real-time lit. G toggles
      fog. A hint line shows the keys.
    - It needs, in `assets/<LEVEL>/`: `actors_decoded.json`, `csfx.json`, `dcs.json`,
      `shd.json`, `particles/`, the decal textures and the ambient WAVs, all copied by
      `sync_godot_assets.py`.
  - **Collision is built at load time** by `scripts/terrain_collision.gd` on the Terrain
    node, which keeps the `.tscn` files under 1 MB:
    - a concave shape of the stitched terrain, with `backface_collision` on because the
      PS1 walls are single-sided;
    - a convex hull per prop mesh.
    It skips the player, because it runs before `player.gd`'s `_ready`. It uses the render
    mesh, not the game's own Ctil collision channels. It leaves out the `_pass` surfaces
    (walk-through floors) and records which faces are `_see` (camera line of sight).
  - Run `--import` first, because a `--script` run that finds textures used in 3D marks
    them for VRAM compression but never reimports them.
  - Parts mounted inside an instanced `.glb` need `set_editable_instance()`, or `pack()`
    drops them.
- `.tscn` rule: every `[ext_resource]` must come before any `[sub_resource]`, or the scene
  fails to load.
- `scripts/player.gd` is the walker, a `CharacterBody3D`. Every generated level scene
  uses it.
  - **Controls** (game default in brackets): W/S along the actor's **+Z** axis (the X1's
    forward) [Up/Down], A/D turn [Left/Right], Q/E strafe [L2/R2], Shift slow walk [L1],
    Space jump, or brake in hover [Triangle], T transform [L1+R1]. The extra actions
    are added to the InputMap at run time.
  - **Physics:** the game's own, decoded from SLUS_007.39. The header of player.gd
    lists every constant and address. It runs in the game's 37.5 Hz steps
    (`vel += cmd − vel·drag`):
    - walker drag 37.5%: run 4.69 u/s, slow 1.95, strafe 3.13; turn 1.84 rad/s, slower
      at speed;
    - three jumps, chosen by a ground probe 1 unit ahead:
      - standing 17→58→59→60;
      - ledge climb 4→27;
      - running 54/55→56/57, landing back into the run cycle;
    - air: gravity 26 u/s², no turning, landing track 5;
    - hover: 5% drag (15% braking, 37.5% at walls, idle ramp after 6 s), 9.4 u/s, the
      turn rate ramps to 2.76 rad/s;
    - steepest slope: 46°/41°/37° (run/strafe/slow), 32°/28° (hover/slow hover);
    - step-up 0.46 walker, 0.96 hover;
    - collision box (legs 3DBB): walker 0.52×0.64, hover 0.64×1.32. It replaces the
      generator's capsule at run time.
  - Tested headlessly: speeds, turn rate and running-jump airtime match the game
    within a few %. The jump apexes come out ~10% low, a step-ordering difference.
  - **Special floors** (`surfaces.gd` and `assets/<LEVEL>/terrain/surfaces.json`). The
    floor under the body is looked up each frame, picking the special floor triangle at
    the raycast ground height. It's applied every step:
    - conveyors move the body: 0.67, 1.34, 2.34 or 4.69 u/s;
    - damage 8–32 per step, or a kill. Health is 5000 and shows bottom left. At zero
      the X1 explodes (player effects 3 and 9, plain sound 0x41; not in water) and
      respawns after 2 s;
    - low traction scales the walker's command and drag;
    - deep water: the default is `WATER_RESCUE`, where a walker turns to hover and a
      hovercraft can't land. Sinking is the game's other setting. LAX2, M4A1, OV and HK
      all start the player on deep water.
  - **Walls:** for terrain walls taller than the step-up height, the next step removes
    the velocity along the wall normal (snapped to x, z or a diagonal), applies 12.5%
    drag and adds a 0x24000 per-axis push. The heading turns up to 8/4096 of a turn per
    step towards the wall direction. A hovercraft touching anything gets a quarter of
    its turn rate.
  - Step-up uses the velocity from before `move_and_slide`, which zeroes it against a
    head-on step.
  - Tested headlessly:
    - conveyor 1.34 u/s;
    - damage 600 HP/s (16 per step);
    - sinking 0.88 u/s, lost at 1.75;
    - hover over water can't transform back;
    - wall bounce and turn;
    - 30 s tours in CONFT, LAX1, JOKE, OV and M3B.
  - **Crouch:** Shift+Space with no forward/back (L1+Triangle): track 3 then hold 25,
    no movement, turning allowed.
  - **Hard landing:** above 0x50000 (0x80000 from tracks 56/57) the landing settle plays;
    above 0x93333 it costs health by 0x80052f54 (`landing_damage()`): a terminal-speed
    fall (0xC0000) is all 5000.
  - Not modelled: aiming, hover hard landings, the crouch's sounds, and what surface bit
    0x10 does (nothing in the EXE reads it).
  - Legs AnmD tracks that share a frame range are exported once. player.gd maps the
    others through the `.glb` extras `duplicate_tracks` (e.g. landing track 5 = track 3).
  - **Spawn:** on its first physics frame it snaps onto the real ground with a raycast,
    because the heightmap estimate can be a few units off (OVMP: by 2.5).
  - **Animation:** each gait plays its legs tracks: start → looping cycle, then a stop
    track for strafes and rest otherwise. The table is `GAITS` in player.gd.
  - **Sounds** (from the game's walker code; see the player.gd header):
    - a positional motor loop per movement (forward 0x22, back 0x24, turn 0x25);
    - step hits at the starts of tracks 39 and 41 (0x38 forward, 0x3a back);
    - a stop sound when the movement changes or ends (0x32/0x34/0x35).
    The ids are Cshd script ids, matched together with the positional flag, because the
    2D and 3D tables reuse ids. They're all in the global table (bank 1), the same in
    every level.
  - **Camera** (`game_camera.gd`, added by player.gd; the generator only sets the lens:
    26.4° vertical FOV, `KEEP_HEIGHT`). From `0x800569ec`/`0x8005612c`:
    - 7 views (V, the game's Select) from the mode table at `0x8009aec4`, each a preset
      list (primary + fallbacks) and flags (zoom 0x100/300 dolly, fixed world yaw, line
      of sight). Views 5/6 only inside class-95 Triggers with bitfield 0x40.
    - Presets at `0x8009ad08` (20 bytes: yaw, pitch, height, look offset). Height
      H(p) = max(4.5, 6.75 + 16(1 − (1 − (p−330)/600)²)); camera Y = H + Ys/2, look Y =
      Ys + offset.y; distance = height difference × cot(pitch).
    - Easing: pitch/yaw 1/32 per **150 Hz** step, capped 52.7°/s and 105.5°/s; Ys is a
      cubic spring (`0x80056530`).
    - Line of sight (`0x80055ee8`): terrain only; a see-through (0x80) first hit is
      rechecked from the player. Blocked → every 0.4 s step to the next fallback
      (higher, never closer).
    - Transform cut-away: a random preset 9–16 with clear sight, held rigidly.
    - The zoom's rate isn't decoded (ZOOM_RATE is a guess).
    The     walker's other sounds: hover loops 0x28–0x2a, transform 0x15.
  - **Testing (2026-10-28):** a scripted walk test showed it lands on the floor in all
    14 levels and walks out of the start bay in most of them.
- `scripts/music_loop.gd` is an AudioStreamPlayer that replays itself when the track finishes.
- `.godot/` and `*.import` are gitignored. Commit the `.uid` files.

## Status

Every resource type in every MIS has a parser, as do the movies, loading screens and
demos. All of it is viewable in the asset viewer.

Almost every field is now confirmed against SLUS_007.39 (function addresses are cited in
each docstring). What's still open:
- **Actors (98.3% of payload bytes decoded; fields confirmed never read count as
  `unused_*`):** weapon +29 (classes 98/99), lightning (88) +50, class 35 +18/+19, class 32
  +14, BasePathed +10, class 27 +18…22, class 34 +12, Trigger +6, Prop +9; the reader of
  class 99 `weapon_category`; most lightning (88) flag names and ring (92) flags
  0x4/0x8/0x20.
  - The effect classes 87–94 have one decoder (tables in decode_actors.py), which
    extract_sfx_meta.py reuses for Csfx records.
  - Corrections from that pass: 87 is a trail ribbon, 88 lightning, 89 a flash disc/star,
    90 a model shatter, 92 a shockwave ring; class 31 is a player `Pusher`.
- **RPN VM / variables:** all messages any script uses are named, and so are all `v[]`
  indices any script touches. Still unknown:
  - `v[0]`, `v[1]`, `v[5]`, `v[18]` and `v[20..22]`: no code or script uses them.
  - `v[56]` codes 1/4/5/8: scripts test them, but no writer was found.
  - Walker state 4 and the meaning of each `v[39]` Sky Captain AI mode.
  - `*ref[1]` is unused.
  - Messages are u8 message + **u8 argument**, so large script arguments are truncated by
    the game itself.
- **Demos:** decoded. Timing values are 1/300 s per frame, and each demo is 60 s. Buttons
  are the game's remapped input word (default config assumed). The retail game only plays
  demos back.
- **Small leftovers:**
  - The Cctr payload is freed unread, so it can't be recovered from the executable.
  - Cvkh +10/+13 and Cnet `unknown_10` are never read by the game.
- **Not yet confirmed by ear/eye:**
  - The SFX sample rates (extract_sfx.py writes 11025 Hz; Cvkh says 16/22 kHz for 734
    tones).
  - The per-class initial yaws in level_layout.gd.
- **Disc coverage:** every file on the PS1 disc is decoded or accounted for. `DUMMY.DAT`
  is 27.6 MB of zeros, `SYSTEM.CNF` is the boot config, and the executable embeds no
  images or audio, only text.
- **Cut content:** the executable loads `brfe3.wve`/`poe3.wve` (an "E3" level's briefing
  and post-mission movies) and `alang.lsc` (a language-select loading screen), none of
  which are on the retail disc. Separately, 10 script references point at actor ids that don't exist (M2C
  469/470, OV 442/346/352, OVMP 219/223). The PC and PS1 builds of OVMP have identical
  actor sets, so these actors were removed before release and the messages go nowhere.

## Conventions

- Python: stdlib plus Pillow/fonttools only, a module docstring describing the format,
  and `_private` helpers.
- Commit messages: a short imperative subject, then a body explaining *why* when the
  change is non-trivial.
- Format findings confirmed by listening tests or visual checks are recorded in the
  script docstrings. Keep them up to date when you learn something new.
