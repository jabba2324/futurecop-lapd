# Future Cop: L.A.P.D. — asset extraction & Godot viewer

Reverse-engineering the PS1 game *Future Cop: L.A.P.D.* (EA, 1998): extract every asset
from the disc with Python, and browse all of it in a Godot 4 asset viewer. (The Godot
project also holds four generated Precinct Assault level scenes.)

## Repo layout

```
parsed/    extractor output, one folder per level (+ parsed/video/) — regenerate with tools/
tools/     Python extractors, lib/ (shared helpers) and run_all.py
godot/     Godot 4.6 project: asset viewer + generated level scenes (assets synced for 4 levels)
README.md  human-facing overview, quick start, how to extract the disc images
```

The game data stays **outside git**, in the repo's parent folder:

```
../Future Cop - L.A.P.D. (USA).iso, ../future_cop_lapd.img/.ccd/.sub   disc images
../ps1/        PS1 disc contents (what the tools read)
  CW/*.MIS       Crime War campaign levels (FE, LAX1, LAX2, M1A1, M2C, M3A, M3B, M4A1, OV, UN)
  PA/*.MIS       Precinct Assault levels (CONFT, HK, OVMP, SLIM, JOKE)
  CW/, PA/       *.LSC loading screens, *.DEM attract-mode demos
  MOVIES/        25 .WVE FMVs;  EA_LOGO.FSV;  SLUS_007.39 = PS1 executable
../pc/windows/ PC disc, ISO 9660 side. MISSIONS/<level> are the PC .MIS files
               (big-endian, forward FourCCs; for comparison only).
../pc/mac/     PC disc, HFS side (Mac version; resource-fork files are MacBinary .bin)
../ghidra/     the analysed Ghidra project of SLUS_007.39 (see External references)
```

Only code is in git. `parsed/` and `godot/assets/` are generated by `tools/run_all.py`
and gitignored, so a fresh clone needs the disc at `../ps1/` and one pipeline run before
the viewer or the level scenes have anything to show. The history was squashed on
2026-10-28; nothing from before then, such as the old `raw/`, `archive/` (BIN/CUE) or the
committed `parsed/`, survives in git.

## Extraction pipeline (`tools/`)

Every script is standalone (`python3 -I tools/<script>.py`) and writes to
`parsed/<LEVEL>/`. They find their inputs with `lib.iff_utils.find_game_files(ext)`, which
returns the sorted `<ps1_dir>/{CW,PA}/*.<ext>` files. `lib.iff_utils.ps1_dir()` is
`$FCOP_PS1_DIR`, or `../ps1` next to the repo. They need Pillow and fonttools;
`extract_videos.py` also needs java and ffmpeg (libtheora).

`tools/run_all.py` runs the steps below in order (`--no-videos`, `--from STEP`), then
`sync_godot_assets.py`. The order matters: objects, terrain and glTF reference the
textures written by `extract_visuals.py`, and `extract_tos.py` checks against `voices/`.

| Script | Resource types | Output in `parsed/<LEVEL>/` |
|---|---|---|
| `extract_visuals.py` | `Cbmp` textures, `Cpyr` particles, `Cfnt` fonts | `textures/cbmpNNN.png`, `particles/`, `fonts/` |
| `extract_objects.py` | `Cobj` 3D models (static, last morph frame) | `objects/cobjNNN.obj/.mtl` |
| `extract_terrain.py` | `Ctil` chunks + `Cptc` grid | `terrain/ctilNNN.obj`, `terrain/map.obj` (stitched, incl. border filler) |
| `export_heightmap.py` | `Ctil` heightmaps | `heightmap.json` |
| `extract_actors.py` | `Cact` / `Csac` instances (raw params) | `actors.json` |
| `extract_sfx.py` | `BGAV` voice, `MGAV` music, `Cvkb` SFX samples | `voices/`, `music/`, `sfx/` |
| `convert_fonts.py` | extracted Cfnt PNG+FNT | `fonts/cfntNNN.ttf` |
| `export_gltf.py` | `Cobj` incl. skeletons (3DHY/3DMI), morphs (4DVL/3DRF), clips (AnmD), UV anim (3DTA) | `models/cobjNNN.glb` |
| `decode_actors.py` | `Cact`/`Csac` per-class fields (45 classes), `CASt` spawn data | `actors_decoded.json` |
| `extract_nets.py` | `Cnet` AI path graphs | `nets.json` |
| `extract_rpns.py` | `RPNS` actor-script pool + SHDR script slots/load conditions; **shared RPN VM disassembler** | `rpns.json` |
| `extract_fun.py` | `Cfun` polled trigger list (condition → action scripts) | `fun.json` |
| `extract_shd.py` | `Cshd` sound table (sound id → bank/program) | `shd.json` |
| `extract_tos.py` | `Ctos` streamed voice/talking-head clip table | `tos.json` |
| `extract_dcs.py` | `Cdcs` decal rectangles (used by class-97 actors) | `dcs.json` |
| `extract_sfx_meta.py` | `Cvkh` tone tables, `Csfx` effect tables, `Cctr` loader markers | `sfx_banks.json`, `sfx_tones/`, `csfx.json`, `cctr.json` |
| `extract_frontend.py` | FE only: `Cmdc` screens, `Ctdt`+`Ctin` VRAM/sprites, `Ctrs` strings, `Cmic` save icon | `FE/frontend/` |
| `extract_canm.py` | `CANM` (MNAC) radio-panel animations in SWVR | `anims/*.png` (64×48 frame strips), `.gif`, `anims.json` |
| `extract_lsc.py` | `.LSC` loading screens (MDEC) | `loading/*.png` |
| `extract_demos.py` | `.DEM` attract-mode joypad recordings | `demos/*.json` |
| `extract_exe_strings.py` | text in the executable `SLUS_007.39` (game text, file names, SDK/debug) | `FE/exe_strings.json` |
| `extract_videos.py` | `.WVE` FMVs + `EA_LOGO.FSV` (via jPSXdec + ffmpeg) | `parsed/video/*.ogv` |

`tools/lib/` holds the shared helpers: `iff_utils.py` (game-file lookup and IFF walker)
and `bs_decode.py` (PS1 MDEC/BS v2 still-image decoder). Tools put `tools/` on `sys.path`
and import `from lib.<module> import …`. Some tools also import other tools'
helpers, e.g. `extract_fun`/`extract_shd` use the VM disassembler in `extract_rpns`.
`sync_godot_assets.py` copies only what `generate_scene.gd` reads from `parsed/<LEVEL>/`
into `godot/assets/<LEVEL>/` and deletes everything else there. Godot's extracted `.glb`
textures (`models/<cobj>_*.png`) are kept.

`lib.iff_utils.iter_iff_resources(data)` is the shared IFF DATA-section walker and yields
`(type, id, payload)`. **It merges resources that share a (type, id)**. Every mission has
two `Csfx` id 1 and two `Cshd` id 1 (a global and a mission table). For those, use the
non-merging `extract_rpns._iter_resources`, which also exposes the SHDR header.

Every script has a detailed format docstring at the top. Read it before changing a parser:
the docstrings are the source of truth for each binary layout. Each docstring states the
confidence of its findings (confirmed vs guessed). Treat the "guessed" actor class layouts
in `decode_actors.py` as hypotheses.

### Format facts that took a lot of trial and error (don't re-derive)

- MIS = EA IFF. The CTRL header holds the MUSIC size at 0x0c, the SWVR size at 0x10 and
  the DATA size at 0x14. The sections follow in the order DATA, SWVR, MUSIC, and the three
  sizes sum to the file size. DATA chunks are aligned to 0x6000, and `LLIF` is fill.
  FourCCs are stored byte-reversed (`bkvC` = `Cvkb`).
- SPU ADPCM: in byte 0, the **low nibble is range/shift** and the high nibble is filter.
  Many docs say the opposite.
- Audio rates confirmed by listening: voice is 11025 Hz mono. Music (MGAV) is 13230 Hz
  stereo, laid out split-half (first half L, second half R), with no end flag.
  - `extract_sfx.py` writes every Cvkb sample at 11025 Hz. According to the Cvkh tone
    tables, 258 tones are really 22050 Hz and 476 are 16000 Hz. That comes from the data
    and hasn't been checked by ear.
  - `sfx_tones/` has each tone at its in-game pitch.
- BGAV clips are grouped by the preceding 36-byte `RVWS` name. Slice the name at the null
  byte, because it is followed by a `\x80` pad. Strip any partial `.stream` suffix as
  well, because the 20-byte field truncates it.
- Cobj vertices: `(-x, y, z) / 512`. Terrain: `world_y = channel_byte / 32`, and each Ctil
  chunk spans ±8 units.
- **Y-inversion is only a skinned-model thing.** Skinned Cobj vertices are bone-relative,
  and the root bone carries a 180° rotation about (1,0,1). The OBJ export skips that
  rotation, so skinned OBJs (e.g. the mech) look upside-down. The `.glb` export applies
  the root rotation, so **never flip `.glb` models**. Static and morph models are upright
  either way.
- X1-Alpha (class 1) is five parts, in `objects` order in every level: legs (walk cycle,
  53 clips), cockpit (wing/hover transform), weapon (×2), beacon lights, pilot. They
  mount on the `.glb` `attach_N` empties (3DHS): cockpit on legs.attach_0, weapons on
  cockpit.attach_0/1, lights on cockpit.attach_2. `level_layout.assemble_x1()` builds it.
  The legs walk cycle is AnmD tracks 38→39→40→41 (looping); track 0 is rest.
- Actor placement: `pos × 8` world units, mapped as in `godot/scripts/level_layout.gd`.
  Cnet nodes use the same `pos_x`/`pos_z` convention (`raw/256`), and every pathed actor
  sits exactly on a node of its net.
- Timing: the game clock advances 5 per VSync (300 Hz on NTSC). Cfun periods, `t[]`
  timers and Csac spawn periods count VSyncs (1/60 s). Model animation (AnmD) runs at
  **10 fps** (3 clock units × 30 per frame; walk tracks scale with actor speed). The CANM
  radio panels are 10 fps and play once.
- RPNS script slots are `on_damage`, `on_destroy` and `on_detect`. A Csac's two SHDR inline
  scripts are its spawn condition and on-spawn action; for other types the second
  inline script is an on-load action.
- Cfun, RPNS and the SHDR script slots all use one RPN bytecode VM. The interpreter is at
  0x80069d68 in SLUS_007.39, with a jump table of 62 opcodes at 0x80011c6c. The opcode
  table is in the `extract_rpns.py` docstring.

### External references

- **fc-mit** (`github.com/Ghoster738/Future-Cop-MIT`, MIT-licensed C++), especially
  `src/Data/Mission/`, is the reference that the terrain, object, glTF, actor, Cnet, Cfun,
  Cshd, Ctos and Cdcs parsers were ported from. Its own bugs that we fixed are noted in the
  docstrings. Clone it into a scratch dir when needed.
- `../ghidra/` (outside git; it was `tools/ghidra_project/` until 2026-10-28) is the
  analysed SLUS_007.39 with PsyQ signatures applied.
  - It needs the `ghidra_psx_ldr` extension (PSX language), which has no Ghidra 12.2 build
    yet. On the Linux box, Ghidra 12.1.4 + ghidra_psx_ldr + a Temurin 25 JDK live in
    `~/.local/opt`.
  - Ghidra refuses project paths containing dot-dirs. The project owner field is `chris`.
  - `../ghidra/decomp.sh <addr>...` decompiles headlessly via `scripts/Decomp.java` (pass
    `list` to list all functions). Each call costs ~1 min of start-up, so batch addresses.
  - Only one process can open the project at a time.
  - The findings (function addresses, layouts) are recorded in the tool docstrings, so
    the project is only needed for further reverse-engineering.
- Video: jPSXdec handles `.WVE`/`.FSV`. It isn't committed: `extract_videos.py` downloads
  the v2.1-beta release on first use, checks it against a pinned SHA-256, and caches it in
  `~/.cache/fc-lapd/` (`JPSXDEC_JAR` overrides). It writes `debug00.log`/`index.log`/`save.log`
  into its cwd, so `extract_videos.py` runs it in a temp dir.

## Godot project (`godot/`)

- Godot 4.6, Forward+. Main scene: `scenes/CONFT_level.tscn`.
  - Linux: `godot` (Godot 4.6.3 in `~/.local/opt`).
  - Mac: `/Applications/Godot.app/Contents/MacOS/Godot`.
- **Asset viewer**: `godot --path godot res://scenes/asset_viewer.tscn`
  (`scripts/asset_viewer.gd`).
  - It reads **`parsed/` directly at runtime**, so all 15 levels work with no copying
    and no import step. `scripts/obj_loader.gd` is a runtime OBJ/MTL loader; glTF,
    PNG, WAV, TTF and Theora files load natively.
  - Categories: Models (glb with animation playback, OBJ fallback), Terrain, Textures,
    Images (particles, loading screens, radio panels, front-end), Fonts, Level (terrain,
    every actor and the Cnet paths; click an actor to inspect its decoded fields), Audio,
    Video and Data (a tree of any JSON).
  - User args after `--` select a view and save a screenshot, e.g.
    `--level M2C --tab Level --item "Cnet 1 " --pitch 60 --shot /abs/out.png`.
    Also `--anim N --seek 0.5` for animations.
- `scripts/level_layout.gd` holds the actor placement shared by the generator and the
  viewer: heightmap sampling, game → Godot position, initial yaw, part stacking and the
  X1 assembly. Change placement there only.
  - Yaw comes from the `STORED_YAW` table: the params word and bits each class's init
    function reads in SLUS_007.39 (see `initial_yaw` in actors_decoded.json).
    - Turret bases have their own yaw (`PART_YAW`).
    - Path followers (5/20/26/28/31) face from their spawn Cnet node towards the next
      node, so the layout needs `nets`.
    - Aircraft and negative prop/pickup values (random or spinning) are left unrotated.
    - This is derived from the code and not yet confirmed visually.
  - Classes 98/99 are weapon definitions and are not placed.
  - Not implemented: the "align to terrain normal" flag (class 11 byte +17 bit 0, turret
    base flags bit 0).
- `scripts/generate_scene.gd` is a headless generator. It builds `scenes/<LEVEL>_level.tscn`
  from `godot/assets/<LEVEL>/`, which `tools/sync_godot_assets.py` fills from `parsed/` for
  **CONFT, HK, OVMP, SLIM**. These include `nets.json` and `models/` (the X1 part
  `.glb`s); the rest are OBJs.
  ```
  python3 -I tools/sync_godot_assets.py CONFT     # parsed/ → godot/assets/
  godot --headless --path godot --import        # first, or textures fail to load
  godot --headless --path godot --script scripts/generate_scene.gd -- CONFT
  ```
  The committed scenes are pure generator output; there are no hand edits. They reference
  `res://assets/...`, which is gitignored, so they only load after `run_all.py`.
  - Per-level extras are constants in the generator: `PLAYER_ACTOR` (player.gd plus the
    chase camera), `SUN_COLOR`, and a Music node from `music/`.
  - Run `--import` first, because a `--script` run that finds textures used in 3D marks
    them for VRAM compression but never reimports them.
  - Parts mounted inside an instanced `.glb` need `set_editable_instance()`, or `pack()`
    drops them.
- `.tscn` rule: every `[ext_resource]` must come before any `[sub_resource]`, or the scene
  fails to load.
- `scripts/player.gd` is attached to Actor_12 in CONFT. W/S moves along the actor's
  −Z axis and A/D turns it. While moving it plays the legs' real walk cycle, and it
  returns to rest when stopped.
- `scripts/music_loop.gd` is an AudioStreamPlayer that replays itself when the track finishes.
- `.godot/` and `*.import` are gitignored. Commit the `.uid` files.

## Status

Every resource type in every MIS has a parser, as do the movies, loading screens and
demos. All of it is viewable in the asset viewer.

Almost every field is now confirmed against SLUS_007.39 (function addresses are cited in
each docstring). What's still open:
- **Actors (98.3% of payload bytes decoded; fields confirmed never read count as
  `unused_*`):** weapon +29 (classes 98/99), lightning (88) +50, class 35 +18/+19, class 32
  +14, BasePathed +10, class 27 +18…22, class 34 +12, Trigger +6, Prop +9; the reader of
  class 99 `weapon_category`; most lightning (88) flag names and ring (92) flags
  0x4/0x8/0x20.
  - The effect classes 87–94 have one decoder (tables in decode_actors.py), which
    extract_sfx_meta.py reuses for Csfx records.
  - Corrections from that pass: 87 is a trail ribbon, 88 lightning, 89 a flash disc/star,
    90 a model shatter, 92 a shockwave ring; class 31 is a player `Pusher`.
- **RPN VM / variables:** all messages any script uses are named, and so are all `v[]`
  indices any script touches. Still unknown:
  - `v[0]`, `v[1]`, `v[5]`, `v[18]` and `v[20..22]`: no code or script uses them.
  - `v[56]` codes 1/4/5/8: scripts test them, but no writer was found.
  - Walker state 4 and the meaning of each `v[39]` Sky Captain AI mode.
  - `*ref[1]` is unused.
  - Messages are u8 message + **u8 argument**, so large script arguments are truncated by
    the game itself.
- **Demos:** decoded. Timing values are 1/300 s per frame, and each demo is 60 s. Buttons
  are the game's remapped input word (default config assumed). The retail game only plays
  demos back.
- **Small leftovers:**
  - The Cctr payload is freed unread, so it can't be recovered from the executable.
  - Cvkh +10/+13 and Cnet `unknown_10` are never read by the game.
  - The "align to terrain normal" flags aren't applied in Godot.
- **Not yet confirmed by ear/eye:**
  - The SFX sample rates (extract_sfx.py writes 11025 Hz; Cvkh says 16/22 kHz for 734
    tones).
  - The per-class initial yaws in level_layout.gd.
- **Disc coverage:** every file on the PS1 disc is decoded or accounted for. `DUMMY.DAT`
  is 27.6 MB of zeros, `SYSTEM.CNF` is the boot config, and the executable embeds no
  images or audio, only text.
- **Cut content:** the executable loads `brfe3.wve`/`poe3.wve` (an "E3" level's briefing
  and post-mission movies) and `alang.lsc` (a language-select loading screen), none of
  which are on the retail disc. Separately, 10 script references point at actor ids that don't exist (M2C
  469/470, OV 442/346/352, OVMP 219/223). The PC and PS1 builds of OVMP have identical
  actor sets, so these actors were removed before release and the messages go nowhere.

## Conventions

- Python: stdlib plus Pillow/fonttools only, a module docstring describing the format,
  and `_private` helpers.
- Commit messages: a short imperative subject, then a body explaining *why* when the
  change is non-trivial.
- Format findings confirmed by listening tests or visual checks are recorded in the
  script docstrings. Keep them up to date when you learn something new.
